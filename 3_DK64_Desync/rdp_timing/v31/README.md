# rdp_timing v31 — 書き込みだけの 1 サイクルスパンを合成で測り直す（MGC 2011 パート 4）

v30 の結果: パート 4 のリストはモードビット（TLUT / ディザ / ポイント / BI_LERP / パース / KEY / FORCE_BLEND / カバレッジ）を
どう変えても実機の時間は ±0.1% で変わらず、傾き 0 でも、テクスチャ無し（0C）でも、シェード無し（0A）でも、エッジだけ（08）でも
同じ（+0.6〜2%）。2 サイクル化で +31%（モデルも +30%）。つまり実機の超過分（ares の 1CYC16 テーブル比 +17〜27%）は
**属性ではなく形（スパンの数・幅・配置）とメモリ側**にあります。デモは **640 px 幅のカラーバッファ（1 行 1280 B）** に
13〜20 px のスパンを 1 三角形あたり約 15 本描き、テーブルは 320 px 幅で測ったものです。

Y 系列（合成、VI オフ、4096 スパン、幅 8 / 13 / 16 / 20 / 32 / 64、1 サイクル・テクスチャ・ブレンド無し・Z 無し = デモと同じ
Set_Other_Modes 下位語 0x0F0A4000、0E 三角形）:
- `wo_rect320` / `wo_rect640`: 垂直エッジのスパン（H=8）、ランダム配置、カラーバッファ幅 320（0 番地付近）と 640（0x600000、デモと同じ）
- `wo_apex320` / `wo_apex640`: 本物の三角形（頂点が上、底辺 2w）
- `wo_rect320_h16` / `wo_rect640_h16` / `wo_apex640_h16`: 1 三角形 16 スパン（デモの 15 に近い）
- `wo_rows640` / `wo_cols640` / `wo_strip640` / `wo_same640`: 同じ列でランダムな行 / 同じ行でランダムな列 / 横に隣接 / 全部同じ場所
- `wo_slopes640` / `wo_shade640`（0C）/ `wo_edge640`（08）
- `blend320` / `blend640`: IMAGE_READ（読み書き）での 320 vs 640（パート 2・3・5 の合っているモード）
- `wo_rect512` / `wo_rect1024` / `wo_rect640_5m`（0x500000）/ `wo_rect320_6m`（幅 320 を 0x600000 に）
- X 系列は `mgc_p4_4316` の full / tri_only だけ（v29/v30 との継続性）。

`Y` 行: case, w, H, triangles, spans, DPC_CLOCK（3 回の最小）, ticks, clk/スパン, clk/三角形, VI プローブ。`ares_reference.txt` = ares series v8。
8 MB 必須、実機で約 3 分。
