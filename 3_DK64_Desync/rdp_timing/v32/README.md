# rdp_timing v32 — 細いスパンと小さい三角形（MGC 2011 パート 4）

v31 の結果: 合成の書き込みだけスパン（幅 8〜64 px）は実機 = ares の 1CYC16 テーブル + 2〜4 clk/スパン、640 px 幅のカラーバッファで
さらに +2 clk/スパン（6% 程度）で、配置（同じ列・同じ行・隣接・同じ場所）・傾き・テクスチャ有無はほぼ無関係。デモのリストの +17〜27% には
足りません。デモのパート 4 の三角形を数えると、**スパン幅の中央値は 8 px、36% のスパンは 4 px 未満**（三角形の縁の細い部分）、
**1 三角形のスパン数の中央値は 12、16% は 4 本以下**です。v31 は幅 8 px 以上しか測っていないので、v32 は幅 1 / 2 / 3 / 4 / 6 / 8 / 16 px と、
1 三角形あたり 1 / 2 / 4 / 8 / 32 本のスパンを測ります（VI オフ、書き込みだけ = デモのモード、640 幅 0x600000）。

- `wo_rect640` / `wo_rect320` / `wo_apex640` / `blend640`: 1 三角形 8 スパン、幅 1〜16
- `wo_rect640_h1` / `_h2` / `_h4` / `_h32`、`wo_apex640_h32`、`wo_rect320_h1`、`blend640_h1` / `_h32`: 三角形の固定費（スパン数を変える）
- `wo_edge640_h1`（08: エッジだけ）/ `wo_shade640_h1`（0C: シェードだけ）: 語数の少ない三角形の固定費
- X 系列は `mgc_p4_4316` の full / tri_only だけ。

`Y` 行: case, w, H, triangles, spans, DPC_CLOCK（3 回の最小）, ticks, clk/スパン, clk/三角形, VI プローブ。8 MB 必須、実機で約 2 分。
