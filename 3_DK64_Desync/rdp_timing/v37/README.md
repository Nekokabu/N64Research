# rdp_timing v37 — ゲームのリストの三角形を形だけ変えて再生（「合成より 10〜20% 高い」の在りか）

v36 で分かったこと: 配置（2 KB ページのずれ）とテクスチャの向きは無関係、シザーの外に出た三角形 1 個 88〜130 clk、幅 0 の行 1 本 44 clk、
エッジが 1 行 8 px ずれる三角形はスパンが 4 サブスキャンラインぶん広がった幅のコスト（+5〜19%）。ただしゲームのリストで数えると
シザー外・幅 0 の分は 1〜2% で、10〜20% には足りません。v37 はゲームのリストそのものの三角形を 1 性質ずつ変えて、
差がどこに付いているかを直接見ます（実機/ares を variant ごとに比べる）。VI オフ、8 MB、実機で約 2 分。

- リスト: `bar_2316`、`bar_i2274`（軽）、`bar_i2314`（重）、`dk64_797`、`dk64_d6373`、`mgc_p4_4316`、`mgc_p2_1802`
- variant: full / tri_only、`tri_vert`（全エッジを垂直に: 各エッジの中間高さの位置で固定）、`tri_halfslope` / `tri_dblslope`（エッジの傾きを 1/2 / 2 倍）、
  `tri_snap`（エッジの x を整数画素に）、`tri_nosmall`（4 行未満の三角形を除く）/ `tri_onlysmall`（それだけ残す）、`tri_shrink`（全三角形を左上を基準に半分の大きさに）
- `X` 行の形式は v22〜v30 と同じ。`ares_reference.txt` = ares series v10。`compare.py 実機ファイル v10`（`v37runs/v10.txt` に置く）。
