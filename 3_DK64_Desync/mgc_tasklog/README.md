# mgc_tasklog — MGC 2011 デモ（Retroactive）の実機フレームタイムライン記録

bar_tasklog / dk64_tasklog と同じ常駐ロガーを MGC 2011 デモに入れるパッチです。デモの libultra の 4 関数
（`osSpTaskLoad` 0x80015010 / `osSpTaskStartGo` 0x8001521C / 例外ハンドラの `send_mesg` 0x8000DFFC / `osSpTaskYield` 0x80015660）を
`j`/`jal` で差し替え、COP0 Count 付きで「グラフィックタスクの起動・RSP 停止（yield / 再開を含む）・DP 割り込み・VI 割り込み」を
4 バイト/件で記録します（形式は bar_tasklog v3 / dk64_tasklog と同じ。ヘッダのマジックは `MGTL`、version 7）。

- デモは「フレーム数ベース」で進みます（nfo にもそう書いてあります: *frame based timing so correct RDP fillrate speed is required*）。
  音楽は実時間で流れるので、**フレームの描画が実機より速いパートがあると映像が音楽より先に進みます**。ares では
  パート 4（スピーカーの部屋）が実機より約 12%、パート 5（ガラスの格子）が約 8% 速く、RETRO ロゴの時点で約 7 秒
  （実機 VI 9050 ≈ 151 秒 vs ares 8620 ≈ 144 秒）先行します。このロガーはそのパート 4 の頭から記録を始めます。
- 記録は **VI 5000 以降で、直前のグラフィックタスク起動から 3.8 VI 以上あいた最初のグラフィックタスク**（= パート 3 → 4 の
  ロードの切れ目。ares では 5 VI、パート 3 のフレームは最長 2.7 VI）で自動的に始まり、96 KB（約 24000 件、パート 4・5 と
  RETRO ロゴのほぼ全部 ≈ 2340 フレーム）溜まるとカートリッジの **SRAM（0x08000000）に書いて停止**します（画面が止まったら完了。
  ares では RETRO ロゴの後のポスターが出た直後）。トリガが掛からなくても VI 10500（約 3 分）で書いて止まります。
- ロガーは RAM 0x807E6000（コード）/ 0x807E7000（状態）/ 0x807E8000〜0x807FFFFF（96 KB バッファ）に常駐します。デモはこの領域を
  使いません（スタックは 0x803FFFF0、最後のカラーバッファは 0x796000 まで。ares でデモ全体を通して 0 のままの領域）。
  拡張パック必須（デモ自体が必要）。

## 必要なもの
- MGC 2011 デモの ROM `mgc_2011.z64`（15,151,240 バイト、.z64/.n64/.v64 いずれも可）— **ROM 自体は同梱していません**。
- EverDrive 64 X シリーズ。セーブタイプを手動で **SRAM 768K**（96 KB）にしてください。メニューに無ければ **SRAM 256K**
  （32 KB: 3 つの 32 KB チャンクを後ろから書くので、32 KB しか無くても最初の 32 KB = パート 4 の前半約 800 フレームが残ります）。

## 手順
1. `python3 make_patch.py mgc_2011.z64 hook.bin mgc_tasklog.z64`（ROM を 0xE80000 まで 0xFF で埋めてロガーを付け、
   エントリに 4 KB をコピーするスタブを入れ、CIC-6102 のチェックサムを再計算します。出力は 15,208,448 バイト）。
2. SD に入れて起動（セーブタイプ: SRAM 768K または 256K）。そのまま放置。パート 4 の頭から記録、RETRO ロゴ → ポスターの
   あたりで画面が止まります（約 2 分半）。
3. リセットして EverDrive のメニューに戻り、セーブデータ（`mgc_tasklog.srm`、96 KB または 32 KB）を送ってください。
4. 解析: `python3 decode_tasklog.py mgc_tasklog.srm`（`--events` で全イベント、`--csv out.csv`）。

## ares 側の参照
`ares_v8.srm` / `ares_v8_frames.txt`（series v8 のハーネス、ROM の RAM ダンプから切り出し）。ares ではパート 4 の記録開始が
VI 5730（VI カウント 5662）、2342 フレームで 3376 VI。パート 4 のフレームは RSP 0.6〜0.73 VI、**DP 割り込みが起動から
1.0〜1.6 VI 後で、CPU はそれを待って 0.005 VI 後に次を起動**（= RDP 律速）。パート 5 は DP 1.7〜2.0 VI、同じく RDP 律速。
実機のログと `dp-go`（RDP）・`go->done`（RSP）・`cpu_gap`（CPU）を比べれば、実機が遅い分がどこに乗っているか分かります。
