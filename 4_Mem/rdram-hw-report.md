# N64 RDRAM 実機調査 報告書 (拡張パックの速度比較・未実装領域の読み出し挙動)

- 著者: Nekokabu <nekokabu@gmail.com>
- 作成日: 2026-11-13
- 対象:
  - N64 実機 (NTSC、8 MiB、拡張パック装着)
  - ares (未実装領域の読み出しを全幅 0 にする変更を適用した版)
  - 計測 ROM: n64_memspeed v1.2、rdram_unmapped v1.0 / v1.1 / v1.2.1 (いずれも筆者作成、libdragon trunk `e356bf3`)

## 1. 概要

N64 の RDRAM について、実機で次の 2 点を調べた。

1. **拡張パックによる速度差。** 公式の拡張パックと非公式品 2 種で、アクセス速度に差があるか。
2. **未実装領域の読み出し値。** RDRAM アドレス空間 (物理 0x00000000〜0x03EFFFFF) のうち、RDRAM が実装されていない領域を読んだとき何が返るか。検証対象は、エミュレータ側の変更「未実装領域の 32bit 読み出しを 0 にし、8/16/64bit と揃える」である。

結果は次のとおり。

| 項目 | 結論 |
|---|---|
| 拡張パックの速度差 | 公式・非公式の間に有意な差はない (全項目で 0.3% 以内、測定ばらつきと同程度) |
| 未実装領域の読み出し | 大部分は 0。全幅で 0 を返す実装は妥当である |
| 例外 | 0.2〜1.6% の確率で、RDRAM デバイスのレジスタ値 (DeviceType / Delay / Row と推定) が返る。頻度はバスの状態で変わる。別の実行でも、出現率と値の構成がほぼ同じに再現した |
| ares との比較 | 1 点だけ実機と異なる。cached (KSEG0) で 0x01000000 のラインを取り込むと、RDRAM 先頭の内容が返る (実機は 0) |

## 2. 根拠資料 (出典)

1. **筆者が作成した計測 ROM による実機計測と、ares 上での実行結果。** ROM の内容は 3 節と 5 節に記す。
2. **RDRAM レジスタの形式。** n64brew.dev の RDRAM ページ ([RDRAM](https://n64brew.dev/wiki/RDRAM?oldid=5375)) と RDRAM Interface ページ ([RI](https://n64brew.dev/wiki/RI)) を参照した。読み出し値をレジスタとして解釈する際にのみ使った。

## 3. 計測方法

### 3.1 n64_memspeed (速度測定)

- **対象ウィンドウ。** 本体 RAM 0x00200000〜 (1 MiB) と拡張パック 0x00600000〜 (1 MiB)。
- **測定項目。**
  - CPU の cached / uncached の連続 read / write (`ld` `lw` `sd` `sw`)
  - memcpy
  - ランダム巡回によるレイテンシ
  - RSP DMA (RDRAM↔DMEM、4 KiB 単位)
  - 全 MiB の読み出し帯域スイープ
- **条件。** 各項目を 3 回実行した最速値。割り込みは禁止した。

### 3.2 rdram_unmapped (未実装領域の読み出し)

0x03F00000 以降の RDRAM レジスタ領域には、試験中アクセスしない (5.3 節の比較も、レジスタを直接読んではいない)。

| 項目 | 内容 |
|---|---|
| 自己診断 | 実装 RAM 上の既知パターンを同じ手順で読み、符号拡張・ゼロ拡張を含めて正しく読めるか確認 |
| 固定ブロック (U) | 7 ブロックで `lb` `lbu` `lh` `lhu` `lw` `lwu` `ld` (uncached)。0x03EFFFFF を含む |
| U+P | 各ロードの直前に、実装 RAM から `DEADBEEFCAFEBABE` を `ld` で読む (前の値が残るオープンバスの検出) |
| cached | D キャッシュを無効化してから、16 B ラインを取り込んで読む |
| RSP DMA | 未実装領域から DMEM へ 64 B 転送。SP DMA のアドレスが 24bit で回り込むかも確認 |
| sweep v1.0 | 未実装領域全体。4 KiB 間隔の `lw` と prime 付き `lw`、64 KiB 間隔の `ld` |
| sweep v1.1 以降 | 未実装領域全体。256 B 間隔の `lw`(+0) と `ld`(+8) を 8 パス。VI 動作中と VI 停止中 (VI_CTRL type=0) の 2 条件 |
| 値の出どころ検索 | 0 以外の値が、実装 RAM と SP DMEM/IMEM のどこにあるかを検索 |
| 書き込み | 未実装アドレスに `sw` して読み戻し。2 MiB 単位のミラーの有無も確認 |
| レイテンシ | uncached `lw` 1 回あたりのサイクル数 |

ロードはすべてインラインアセンブラの 1 命令で発行し、割り込み禁止中に実行した。U+P で、直前の `ld` の直後に対象のロードが来ることは逆アセンブルで確認した。

v1.2 以降は、SD に保存する内容と同じものを ISViewer にも出力する。SD を扱えないエミュレータでも結果を確認できる。v1.2.1 で、libdragon のコンソールが stderr に複製する機能 (初期値で有効) を `console_set_debug(false)` で止め、ログの 2 重出力を解消した。試験内容は v1.1 と同一である。

## 4. 結果 1: 拡張パックの速度比較

### 4.1 拡張パック領域 (0x00600000〜) の比較

| 項目 | 公式 | カラット | 青 | 最大差 |
|---|---|---|---|---|
| cached read ld / lw (MB/s) | 35.69 / 32.32 | 35.69 / 32.32 | 35.69 / 32.30 | 0.06% |
| cached write sd / sw (MB/s) | 20.57 / 20.56 | 20.57 / 20.56 | 20.57 / 20.56 | 0 |
| memcpy (MB/s) | 12.14 | 12.14 | 12.14 | 0 |
| uncached read ld / lw (MB/s) | 20.56 / 10.59 | 20.56 / 10.59 | 20.56 / 10.59 | 0 |
| uncached write sd / sw (MB/s) | 38.90 / 21.15 | 38.91 / 21.16 | 38.91 / 21.16 | 0.05% |
| random cached / uncached (ns) | 490.19 / 480.05 | 490.21 / 480.00 | 490.24 / 480.07 | 0.01% |
| RSP DMA RDRAM→DMEM / DMEM→RDRAM (MB/s) | 366.89 / 385.89 | 366.93 / 386.39 | 367.04 / 385.39 | 0.26% |

### 4.2 判断の根拠

- **ばらつきの目安。** 本体 RAM 側は 3 回とも同じハードウェアを測っている。それでも次の幅で揺れた。
  - DMEM→RDRAM: 388.81〜388.89 MB/s
  - MiB 0 の uncached read: 19.19〜19.40 MB/s
- **パック間の差。** 拡張パック側の差はこの幅に収まる。
- **命令あたりのサイクル数。** 3 種で小数第 1 位まで一致した (uncached ld 36.4、random miss 45.9)。

### 4.3 パックに関係なく見られた傾向

3 種とも同じ傾向だったので、パックの違いではない。

- **RSP DMA の読み出し。** 拡張パック領域のほうが本体 RAM 領域より約 3.7% 速い (約 367 対 約 354 MB/s)。原因は未確定。
- **MiB 0。** cached / uncached の読み出しが 4〜6% 遅い。フレームバッファかコードとの競合と見られる。

### 4.4 制限

- 速度測定では非公式品の品質を判断できない。
- 非公式品の差は、速度より温度や長時間動作時のビットエラーに出やすい。全領域の読み書きテスト (n64_memspeed の B モード) は、本報告の時点で未実施である。

## 5. 結果 2: 未実装領域の読み出し

### 5.1 0 が返った項目

| 項目 | 結果 |
|---|---|
| 自己診断 | OK |
| 固定ブロック、全幅、U / U+P (v1.0・v1.1・v1.2.1 各 196 件) | v1.0・v1.1 は 1〜2 件を除き 0、v1.2.1 はすべて 0 |
| cached (6 ブロック × 8 ロード) | すべて 0 |
| RSP DMA (16 MiB 未満、64 B) | すべて 0 |
| 書き込み → 読み戻し | 書き込みは無視され、0 が返る。2 MiB 単位のミラーなし |
| オープンバス (U+P、v1.0 sweep 14,080 回) | 直前の CPU 読み出し値が返った例は 0 件 |
| レイテンシ (uncached lw) | 実装領域 37.2、未実装領域 36.8〜36.9 CPU サイクル (同等) |

### 5.2 SP DMA の 24bit 回り込み

0x00FFFFF8 から 16 B を DMA 転送すると、DMEM には次のとおり入った。

- 前半 8 B: 0 (未実装領域)
- 後半 8 B: `08000120 00000000` (RDRAM 先頭 0x00000000〜0x00000007 と一致)

SP DMA の RDRAM アドレスは、0x00FFFFFF の次が 0x00000000 に回り込む。v1.0 の RSP DMA 試験で出た NG 1 件は、この回り込みによる試験 ROM 側の不具合で、v1.1 で修正した。

### 5.3 0 以外の値の出現

**出現率 (sweep、各条件 3,604,480 回)**

| 条件 | v1.1 | v1.2.1 | 値の種類 |
|---|---|---|---|
| VI 動作中 | 8,274 件 (2,295 ppm) | 8,338 件 (2,313 ppm) | 48 以上 (記録表が満杯) |
| VI 停止中 | 56,155 件 (15,579 ppm) | 56,127 件 (15,571 ppm) | 4 |

v1.0 の sweep (4 KiB 間隔、VI 動作中) では、`lw` で 4 / 14,080 件、`ld` で 2 / 880 件だった。

**出た値 (出現回数は VI 動作 / 停止)**

| 値 | ロード | v1.1 | v1.2.1 |
|---|---|---|---|
| `B4190010` | lw | 2,068 / 14,039 | 2,063 / 14,033 |
| `2B3B1A0B` (ld の上位 32bit、下位は 0) | ld | 4,134 / 28,078 | 4,166 / 28,064 |
| `FE03FE03` | lw | 1,621 / 10,525 | 1,616 / 10,521 |
| `xxxxFE03` (上位 16bit が 40 種以上で変化) | lw | 計 400 前後 / 0 | 計 400 前後 / 0 |
| `E200FE03` | lw | 0 / 3,513 | 0 / 3,509 |

固定ブロックでの 0 以外は、v1.0 の U+P `lbu` 0x00C00000 = `B4`、v1.1 の U `lbu` 0x01000000 = `B4` と U `lhu` 0x01000000 = `B419` である。いずれも `B4190010` の先頭部分と一致する。v1.2.1 では 0 件だった。

**再現性 (v1.1 と v1.2.1 の比較)**

- 出現率は、両条件とも 1% 以内で一致した。
- VI 停止中に出る値 (`B4190010` / `2B3B1A0B` / `FE03FE03` / `E200FE03`) と、その件数の比も同じだった。
- VI 動作中の `xxxxFE03` は、上位 16bit の値の集合が実行ごとに異なった。v1.1 は主に 0x02xx〜0x03xx、v1.2.1 は 0x01xx〜0x02xx。時間で変わるレジスタ値と見て矛盾しない。

**否定された説明**

- **VI のフレームバッファ転送の残り。** VI を止めると出現率は約 7 倍に増えた。
- **実装 RAM のデータの残り。** どの値も、実装 RAM と SP DMEM/IMEM のどこにも存在しなかった。
- **CPU の直前の読み出し値。** U+P で 1 度も現れなかった。

### 5.4 値の解釈: RDRAM レジスタ値

2 節の資料にあるレジスタ形式と照合した。

**`B4190010` = DeviceType (オフセット 0x000)**

| フィールド | 値 |
|---|---|
| ColumnBits | 11 |
| Bn | 1 |
| BankBits | 1 |
| RowBits | 9 |
| Version | 1 |
| Type | 0 |

2048 列 × 512 行 × 2 バンク × 9bit で 18 Mbit (2 MiB) となり、本体の RDRAM 構成と一致する。

**`2B3B1A0B` = Delay (オフセット 0x008)**

各バイトの下位 3bit がビット数 (3, 3, 2, 3)、上位が設定値 (AckWin=5、Read=7、Ack=3、Write=1) と読める。この設定値は、初期化時に書き込まれる 0x18082838 (AckWin 5 / Read 7 / Ack 3 / Write 1) と一致する。

**`xxxxFE03` / `FE03FE03` / `E200FE03` = Row (オフセット 0x200、各バンクで現在センスしている行) と推定**

次の 2 点が裏付けになる。

- VI 動作中は上位側が 40 種以上に変わった。VI 停止中は 2 種に固定された。VI の DMA がセンス中の行を変えると考えれば説明がつく。
- VI 停止中の出現回数は、DeviceType と Row 系 (`FE03FE03` + `E200FE03`) でほぼ同数だった (v1.1: 14,039 対 14,038、v1.2.1: 14,033 対 14,030)。256 B 間隔の `lw` は、bit9 = 0 の位置と bit9 = 1 の位置を同数読んでいる。`ld` の件数 (28,078 / 28,064) は、`lw` の合計とほぼ等しい。

**アドレスとの対応 (推定)**

| 読んだ位置 | 返った値 |
|---|---|
| `lw`、オフセット (mod 0x400) が 0x000 / 0x100 | DeviceType |
| `lw`、オフセットが 0x200 / 0x300 | Row |
| `ld` (+8) | 上位 32bit がすべて Delay、下位は 0 |

`lw` の対応は、各値が最初に出たアドレスと出現回数の比から推定した。v1.2.1 の初出アドレスも同じ規則に従った (`FE03FE03` @0x00880E00、`B4190010` @0x00980D00、`E200FE03` @0x00900200)。位置ごとの完全な集計は取っていない。

### 5.5 ares との比較

同じ ROM (v1.2) を ares で実行し、ISViewer の出力を実機の結果と比べた。

| 項目 | 実機 | ares |
|---|---|---|
| 固定ブロック、全幅 (uncached) | 0 | 0 |
| cached 0x00800000 / 0x00C00000 / 0x00FFFFF0 / 0x02ABCDE0 / 0x03EFFFF0 | 0 | 0 |
| **cached 0x01000000** | **0** | **`lw` +0 = `08000120`、`ld` +0 = `0800012000000000` (RDRAM 0x00000000 の内容)** |
| RSP DMA、SP DMA の 24bit 回り込み | 5.2 節のとおり | 実機と同じ |
| sweep の 0 以外 | 2,313 / 15,571 ppm (RDRAM レジスタ値) | 0 件 (両条件) |
| 書き込み | 無視される、ミラーなし | 同じ |
| レイテンシ (uncached lw、実装 / 未実装) | 37.2 / 36.8 サイクル | 35.0 / 35.0 サイクル |

- **cached 0x01000000 の差。** ares のキャッシュの取り込み経路で、RDRAM アドレスが 16 MiB 境界で 0 に回り込んでいると見られる。実機では、CPU のキャッシュ経由の読み出しは回り込まない。回り込むのは SP DMA だけである。uncached の同じアドレスは ares でも 0 なので、差はキャッシュの取り込み経路に限られる。
- **sweep の差。** レジスタ値の混入は ares では起きない。5.6 節の判断どおり、再現は不要と考える。

### 5.6 エミュレータ実装への含意

- **0 を返す実装は妥当。** 未実装 RDRAM の読み出しで全幅 0 を返す実装は、実機の通常の挙動と一致する。キャッシュ経由の読み出しと RSP DMA も 0 で、書き込みは無視され、ミラーもない。検証対象の変更 (32bit も 0 に揃える) を支持する結果である。
- **レジスタ値の混入は再現不要。** 実機では 0.2〜1.6% の確率で RDRAM レジスタ値が混じる。ただし頻度がバスの状態 (VI の動作など) に左右されるため、決定的に再現するのは現実的でない。この挙動に依存するソフトも想定しにくい。
- **回り込みの扱い。** 24bit で回り込むのは SP DMA だけである。CPU のキャッシュの取り込み (ラインフィル) は、0x01000000 以上でも回り込まず 0 を返す。ares はキャッシュの取り込みで回り込むため、修正の候補である。

## 6. 今後の課題

- **ares の修正。** キャッシュの取り込み経路で、0x01000000 以上の RDRAM アドレスが回り込まないようにする。修正後に rdram_unmapped で再確認する。
- **レジスタとの直接比較。** 本物のレジスタ (0xA3F00000〜) を読み、混入した値と照合する。
- **対応表の確定。** 0x400 範囲の全オフセットを `lw` / `ld` で読み、オフセットごとに返る値を集計して、アドレスとレジスタの対応を確定する。
- **出現率の変化の原因。** VI を止めると出現率が上がる理由を調べる (RI の自動電流キャリブレーションやバスの空きとの関係)。
- **他の構成での再現確認。** 4 MiB 機、他の拡張パック、PAL 機で再現するか。
- **全領域の読み書きテスト。** 各拡張パックで、温まった状態も含めて実施する。
